# 统一工作区运行时组合

近期学习、摘要和 Obsidian 摄取功能都需要解析当前工作区、捕获预期绑定、在慢操作后校验绑定，并组合仓库与备份提供方。我们决定新增 `WorkspaceRuntime` 深模块，放在 `Workbench/server/workspace-state/workspace-runtime.mjs`，由它统一提供只读解析、写入解析、预期绑定和按需仓库组合；Vite 插件只保留薄的路由适配与装配。绑定变化时操作必须失败，不得自动切换工作区；路由适配器负责把稳定领域错误转换为 HTTP 响应。迁移按 learning → summary → ingestion → radar/backup 分阶段完成，以保持每阶段可独立验证。

## 考虑过的方案

- 让每个路由自行拼装绑定与仓库：接口重复，锁顺序和重绑定语义会继续扩散。
- 把所有逻辑直接放进 Vite 插件：短期改动少，但组合模块会继续变浅。
- 一次性重写全部调用方：提交和回归范围过大，难以定位问题。

## 后果

- 调用方使用 `WorkspaceRuntime` 的显式领域入口，不直接构造绑定身份。
- 读取使用 `mode: "read"`，不创建工作区；变更使用 `mode: "write"`，允许初始化。
- 旧辅助函数在迁移期间作为内部适配器保留，全部调用方迁移并通过回归后删除。
