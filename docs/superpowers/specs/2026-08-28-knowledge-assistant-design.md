# 知识库助手：受控问答与确认入库

日期：2026-08-28

状态：用户已确认，进入实现。

## 1. 目标和范围

在已有本地 Workbench 中增加 Claudian 风格的右侧问答面板。用户可以检索自己的 DBA 文档和脚本、连续追问、查看原文引用，并将检索结果整理为新的知识库文档。

采用受控 Agent：模型可以多轮调用应用提供的搜索、片段读取工具；不能运行命令、访问任意文件、联网检索或直接写入 Vault。入库是独立的、由用户点击确认的服务器操作，不是模型工具。

本期包含：

- 问答入口、侧边对话、流式回答、停止生成、新建会话、本地历史。
- 当前文档上下文与 `@文件` 选择；检索整个已允许索引的资料集合。
- 多轮检索、证据引用、缺失/冲突提示。
- 整理 Markdown 草稿、继续修改、预览并确认创建新 Wiki 文档。
- 复用用户现有模型网关配置的后端适配器；以合成数据验证连接兼容性。

不包含：完整嵌入 Claudian、导入其历史、任意 Skill/Bash、执行 SQL、自动修改既有 Wiki、修改索引 Markdown 文件、OCR、压缩包解包、向量数据库、外网搜索、后台自动入库、团队共享或公网部署。

## 2. 用户交互

主导航增加“知识库助手”；点击后打开右侧常驻面板，不丢失当前页面。宽屏支持边看资料边聊，窄屏使用全宽面板。阅读器增加“加入问答”入口，将选中的文档以可移除标签显示在输入区。`@文件` 从现有索引选择，不接受任意本地路径。

面板包含会话列表/新建会话、问答/整理入库模式、消息区、来源卡片、上下文标签、输入框和发送/停止按钮。折叠面板不取消生成；点击停止或新建会话时显式处理正在运行的任务。每个会话同时只允许一个任务，防止连续点击重复发送。

可见过程只展示工具操作，例如“搜索：ASM 扩容”“读取：某操作手册”；不展示或保存模型隐藏推理。回答和草稿用安全 Markdown 渲染，禁用原始 HTML、自动加载远程图片及危险链接协议。

点击引用调用现有文档阅读器。引用绑定文档 ID、Vault 相对路径、读取时内容指纹和片段位置，不依赖同名文件搜索。原文失效时显示“来源已变更/不可用”，不跳转到猜测的文件。

模型未配置、连接失败、超时或返回不兼容数据时显示真实错误和重试入口，不回退为演示或假回答。首次使用说明：提问、有限聊天上下文和选中/检索到的资料片段会发送到配置的模型服务；不是全本地模型推理。

## 3. 后端与数据流

沿用 React/Vite、本地 Node API、现有 Vault 索引和文档读取能力，不另开数据库服务。新模块分开负责模型传输、检索与证据、会话状态、草稿/入库、API 编排，避免继续堆入既有大型阅读解释服务。

一次问答的顺序：校验用户请求与会话 → 建立有限上下文 → 请求模型 → 校验并执行允许的只读工具 → 继续模型调用 → 验证来源标记 → 保存消息并结束。任务停止、浏览器流断开或服务关闭时中止上游请求，已接收的部分回答标为未完成。

允许的模型工具只有：

1. `search_documents(query)`：调用现有全文检索，返回有限结果的 ID、标题、相对路径和短摘要。
2. `read_document(documentId, start, length)`：读取已索引且仍通过路径策略的文档片段，返回证据编号和内容状态。

工具参数使用严格 schema，拒绝未知工具、额外字段、任意绝对路径和越界读取。初始检索可使用用户问题和指定文件；后续由模型调整关键词及补读。无需建立向量库，但必须测试中文问句、数据库缩写、报错码和同名脚本的检索。

默认预算：单次问题最多 8,000 字符，最多附加 8 个文档；单次搜索返回最多 12 项；单次读取最多 8,000 字符；每任务累计资料正文最多 64,000 字符；历史最多最近 12 条且合计不超过 24,000 字符；最多 8 轮模型调用、16 次工具调用；全局最多 2 个模型任务；任务总时限 180 秒。预算耗尽时给出明确提示，不能无限检索或静默丢弃导致结论失真。

工具结果中的文档文本是待分析数据，而不是指令。服务端工具权限和写入确认不受提示词、检索资料中的命令或模型输出控制。对无来源的结论标明是一般建议，不能伪造本地证据；没有可用来源时不生成“基于资料”的入库草稿。

## 4. 模型连接和本地持久化

模型适配器由后端读取明确启用的本地配置。优先允许显式 Workbench 环境变量覆盖，否则使用已授权的本机 Claude 配置中的网关地址、令牌和模型名。只读取需要的配置字段，不加载其 hooks、权限、系统提示词或自动执行工具。

前端不接收密钥、完整网关配置或凭据文件路径；模型服务只接收构建好的消息。浏览器不能提交任意上游 URL 或更改认证。禁止自动跟随跨地址重定向，日志和客户端错误不包含 Authorization、完整上游响应或私密正文。使用已有网关不代表模型在本机运行；HTTP 网关连接应在设置状态中提示未加密传输。

实现时先用合成问题验证网关的消息格式、流式响应、工具调用、停止与错误处理。若其不支持原生工具调用，不能悄悄声称支持受控 Agent；应报告具体兼容问题，再决定是否使用严格校验的结构化动作协议。不会改动用户 Claudian 的配置。

会话、未完成消息、草稿和入库回执保存到操作系统用户应用数据目录下按 Vault 标识隔离的专用目录，不放进 Vault 或本项目仓库。会话 ID 由服务端生成，文件访问不能由客户端路径决定。持久化使用串行队列和临时文件替换，损坏记录显示错误且不覆盖原记录；历史仅加载必要部分。首期提供新建、列表和恢复会话，不自动删除历史。

## 5. 整理入库与写入边界

用户可从当前讨论进入“整理入库”，描述整理目标。模型生成草稿，不直接保存。草稿预览包含标题、建议分类、完整 Markdown、来源清单、生成标识、资料冲突和待核实项；DBA 操作手册通常包含适用环境、前置检查、步骤、风险、回滚、验证，缺失内容明确标注，不凭空补全危险命令。

用户可继续要求修改，或在草稿编辑区编辑正文、标题和分类。任何修改产生新的草稿版本；预览和确认必须对应同一份内容。

第一版创建位置仅允许 `wiki/concepts`、`wiki/references`、`wiki/questions` 下的直接子级 `.md` 文件，默认 `wiki/concepts`。路径由服务器根据白名单分类和安全文件名生成，不允许任意深层路径。已有的 `wiki/index.md`、`wiki/log.md`、热缓存、其他文档和所有原始资料都不更新。是否扩大分类范围以后单独配置。

保存流程：

1. 草稿版本与实际预览内容、目标路径、来源指纹在服务器端绑定，生成单次有效的确认标识。
2. 用户点击“确认入库”；客户端提交草稿 ID、版本和确认标识，不直接提交任意写入指令。
3. 服务端检查功能开关、同源请求、草稿归属、版本/哈希、来源未变及目标安全性。确认标识 30 分钟过期，过期须重新预览。
4. 拒绝路径穿越、反斜杠、绝对路径、Windows 保留名/备用数据流、隐藏文件、符号链接或目录联接及已有文件。确认前来源变化要求刷新草稿，不自动重新生成后保存。
5. 采用独占创建确保不覆盖；并发确认按草稿串行，完成后记录创建回执。重试返回同一回执或明确冲突，不创建重复文件。写入中断不报告成功，并保留可诊断状态。
6. 只通知现有索引重建新增路径；如果文件已保存但索引失败，应显示“已保存，索引待重试”，不能再次写入。用户可直接打开新文档。

现有只读模式保持开启。为本模块分别增加明确的问答开关与确认创建开关：问答开关允许有限聊天/草稿操作，确认创建开关只允许上述单一写入能力。所有既有笔记写入、AI 工作流、程序启动等禁止状态保持不变；不能通过把全局只读设置改为 false 来实现。

本期不支持覆盖、删除或编辑已有 Vault 文档；若同名，提示用户更换标题。模型只生成建议，永远拿不到确认标识，也不能调用提交接口。

## 6. API 与安全契约

新增独立 `/api/knowledge-chat/` 命名空间，提供状态、会话列表/详情/创建、消息流、草稿预览/修订及确认创建端点。具体 handler 保持在新路由模块中，原 Vite 插件只负责依赖注入和挂载。

所有新端点校验 Host/Origin；改变会话/草稿状态以及调用模型的请求使用 POST、JSON 和同源校验，不通过 GET 触发模型费用或写入。只读全局拦截器仅放行已启用的新模块明确路由，不能用宽泛路径前缀放过其他写入。

POST 消息流使用 fetch 可读取的 SSE 格式，事件包含状态、已验证工具摘要、可显示文本增量、来源、草稿就绪、结束或脱敏错误。一个 run ID 关联全部事件，客户端缓冲被拆开的 UTF-8/SSE 帧并在恢复会话时显示最终持久化状态。

服务端限制请求体、工具结果、消息数量和输出大小。跨会话引用、未知文档 ID、未索引凭据文件、外部路径以及格式损坏的模型动作都拒绝。已有的私密路径过滤沿用，但不承诺自动识别正文中所有敏感信息；界面提示用户在发送前检查选中的生产资料。

## 7. 验收标准

- UI：问答入口明确可见；面板开关、连续追问、新建/恢复、当前文档、`@文件`、来源打开、停止、草稿编辑和确认保存可用；真实错误有明确状态。
- 检索：合成 Oracle/PostgreSQL 资料能多轮搜索与读取；中文问题可找到证据；两个同名 SQL 引用到正确文件；无资料不伪造来源；预算限制可测试。
- 模型：使用合成上下文验证实际网关的流、工具请求、取消及错误；不向服务发送整个 Vault 或凭据。
- 只读：聊天、生成草稿、取消和失败都不改变测试 Vault；未知模型工具不能运行 shell；原有受限 API 仍返回拒绝。
- 入库：未确认不创建；确认仅新增白名单中的 Markdown；原文保持不变；标题碰撞、过期确认、重复点击、篡改正文/路径、来源变化、路径穿越和 Windows junction 均有回归测试。
- 持久化：重启后恢复会话和草稿；不同 Vault 隔离；中途断开/写入失败不展示假成功。
- 现有功能：材料阅读、全文检索、Wiki、知识星图、实时索引保持可用；构建与隐私扫描通过，完整测试结果明确区分已知 Windows 基线失败与新增回归。
- 实际 Vault 的写入验收必须由用户对真实草稿逐篇确认；自动化仅在合成临时 Vault 写入，不为演示自动创建真实知识文档。

## 8. 设计自检与交付顺序

本文不包含用户真实路径、网关地址、凭据、聊天或资料正文。功能范围、只读例外和新增文件边界已分开；模型支持以真实合成探测结果为准，不以配置存在等同连接成功。

实施顺序：模型兼容探测和接口测试 → 受控检索/会话服务 → 问答 UI → 草稿与确认入库 → 集成/安全回归及本地联调。具体任务、文件和测试命令在本文确认后的实现计划中展开。
